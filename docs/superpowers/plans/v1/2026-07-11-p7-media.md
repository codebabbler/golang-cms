**Goal:** The media subsystem — presign → direct PUT → finalize (bytes never touch the binary), the deletion outbox, media-less mode returning `503 unavailable`, finalized-reference enforcement in `Document.Set`, and read-time delivery URLs — so UAC-1.5 passes against a disposable S3-compatible store.

**Architecture:** Implements 02's `media.Service`, 04's Upload Flow (EC-9), 07's Media Deletion, BR-MEDIA-1…3/5/6. The storage SDK is confined to `internal/media` (depguard rule from P1 goes hot). Integration tests run against MinIO in the same disposable-container pattern as Postgres.

## Global Constraints

- Bytes never transit the binary: no method accepts file content (BR-MEDIA-1 [structural] — preserved by construction; no upload-proxy route exists).
- Presign (04): body `{filename, mime, size}`; `size > 50 MB` (V1 compile-time constant, `50 * 1024 * 1024`) → `413 payload_too_large`; `mime` validated against the closed compile-time allowlist — raster images (`image/jpeg`, `image/png`, `image/gif`, `image/webp`, `image/avif`), video (`video/mp4`, `video/webm`), audio (`audio/mpeg`, `audio/ogg`, `audio/wav`), `application/pdf` — anything else rejected before a URL is issued. URLs expire in **15 minutes**; the declared `Content-Type` (and `Content-Length`) are signed into the presigned PUT so the client cannot swap them; finalize re-verifies both against the storage `HEAD` (04).
- Finalize flips `pending → finalized` ONLY after `HEAD` confirms the object exists within the declared size and type (BR-MEDIA-2, 02 guarantee); sets `finalized_at`.
- `Document.Set` rejects `media` values referencing non-finalized rows (BR-MEDIA-3) — the P4 `MediaVerifier` seam goes live.
- Deletion (07 §Media Deletion, BR-MEDIA-5): destructive-gated (RequireRecentAuth 4 h + typed confirmation of the media row's `id`); referenced rows blocked by the inline `ON DELETE RESTRICT` FK → `409` naming the referencing record; success = ONE transaction deleting the row + inserting `object_key` into `cms_media_deletions`; the storage object is deleted after commit (10 s call timeout) and the queue row cleared on success — a 404 from storage counts as success. Retention retries queue rows > 1 h old (P8).
- Media-less mode (BR-MEDIA-6): `Config.S3 == nil` → presign/finalize/delete return `503` code `unavailable`; listing works (rows may exist from a previously-configured epoch); everything non-media is unaffected.
- Every S3 call (presign signing, HEAD, object delete) carries a **10 s** context timeout (09 §Timeouts).
- Delivery URLs resolve at read time: `R2_PUBLIC_BUCKET_URL` + `/` + `object_key` (07); media fields serialize as `{id, url, mime, size_bytes}` for finalized rows (url omitted in media-less mode or when `R2_PUBLIC_BUCKET_URL` is empty), `null` when the row is missing.
- `object_key`: `media/<uuidv7-of-row>/<sanitized-filename>` — sanitize to `[a-zA-Z0-9._-]`, cap 100 chars; uniqueness comes from the UUID segment.
- Audit: `media.presign`, `media.finalize`, `media.delete` (BR-AUDIT-1).
- Waiver shrink: `BR-MEDIA-2 3 5` (BR-MEDIA-2's orphan-sweep half is P8's retention duty; the finalize-verification half is tested here — both halves may carry tests, the waiver clears now).
- `WriteError` only; commits plain; branch `main`.

### Task 3: Deletion with the outbox

**Files:**
- Modify: `internal/media/service.go`
- Test: extend `service_integration_test.go`

**Interfaces:**
- Produces: `(*Service).Delete(ctx, p access.Principal, mediaID uuid.UUID) error` — ONE tx: `DeleteMedia` + `InsertMediaDeletion`; SQLSTATE 23503 (a `media` column references the row) → `ErrReferenced{Table string; RecordID uuid.UUID}` (handler → 409 naming both; the referencing row is found by querying the violating table from the pg error's `TableName` for the first matching id).
