# V3-P2 — Carts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** End users hold server-side cart state attached to their JWT identity (F-28) — pure Postgres, no external service, no stored prices.

**Architecture:** One `cms_carts` row per end user (`end_user_id UNIQUE`, FK CASCADE so GDPR erasure is free), line items as JSONB references `{record_id, collection_id, qty}`. Money is never stored in the cart: hydration reads current prices from records at every `GET`, and items whose record was since unpublished or de-commerced surface as `"stale": true` rather than vanishing. **This phase is public-API-only (no admin surface — the D-V3-2 exception class); its slice is verified by API-level e2e.** All cart routes sit behind `RequireCommerce` + an end-user JWT gate.

**Tech Stack:** Go 1.25, pgx/v5, sqlc.

## Global Constraints (spec: `docs/superpowers/specs/2026-07-14-v3-implementation-phasing-design.md`)

- Authority chain: `docs/BUSINESS_RULES.md` > `docs/architecture/*` > skills > code.
- SQL for collection tables only in `internal/query` (BR-SCHEMA-3) — cart hydration reads records through a query-package helper; `cms_carts` SQL lives in sqlc.
- Money is integer minor units; carts are single-currency — first add pins the collection's configured currency, a different-currency add → 422 naming both (spec B1).
- Cart limits: `qty` 1–99, ≤ 50 distinct items (spec §D2). Errors only via `httpapi.WriteError`; migration `0010`; audit vocabulary +`commerce.cart.update`, `commerce.cart.clear`.
- Done = `make test && make trace` green plus this plan's acceptance sweep.

### Task 2: Cart service + hydration

**Files:**
- Create: `internal/commerce/cart.go`, `internal/query/commerce.go`
- Modify: `internal/audit/actions.go`
- Test: `internal/commerce/cart_test.go`

**Interfaces:**
- Consumes: `schema.Cache` snapshot (`Collection.Commerce`), sqlc from Task 1.
- Produces:
  - `query.CartHydrate(snap, col) (sql string, priceCol, displayCol string, err error)` — `SELECT id, status, "<price>", "<firstText>" FROM "c_<slug>" WHERE id = ANY($1)` (trashed rows excluded by the standard `deleted_at IS NULL`); `displayCol` = the collection's first `text` field by position, empty selection when none (spec §D2 pin).
  - `commerce.CartItem{RecordID, CollectionID uuid.UUID; Qty int}`; `commerce.HydratedItem{CartItem; Display string; UnitAmount int64; Stale bool}`; `commerce.Cart{Currency string; Items []HydratedItem}`.
  - `commerce.NewCartService(q *store.Queries, pool, cache *schema.Cache, rec *audit.Recorder, log) *CartService` with:
    - `Get(ctx, userID) (Cart, error)` — hydrates every item (one `CartHydrate` query per distinct collection in the cart); `Stale=true` when: record missing/trashed, `status != 'published'`, collection no longer commerce-enabled, or currency no longer matches; stale items keep their last-known `Display` blank and `UnitAmount` 0.
    - `AddItem(ctx, userID, in CartItem) (Cart, error)` — validation in order: collection exists + `Commerce.Enabled` (else `ErrNotCommerce` → 422 naming the collection); record exists, not trashed, `status='published'` (else `ErrNotPurchasable` → 422); `Qty` 1–99 (`ErrBadQty`); currency pinning — empty cart adopts the collection's `Commerce.Currency`, mismatch → `ErrCurrencyMismatch` → 422 naming both; existing item → qty replaced; else append; > 50 distinct → `ErrCartFull` → 422. Audit `commerce.cart.update` (detail: record_id, qty — never prices).
    - `SetQty(ctx, userID, recordID, qty)` (absent item → `ErrNoSuchItem` → 404), `RemoveItem(ctx, userID, recordID)`, `Clear(ctx, userID)` (audit `commerce.cart.clear`).

## Self-Review Notes (execution-time attention)

- **Admin sessions get 401 on cart routes** — deliberate: a cart binds to a JWT identity (F-28); letting admin cookies own carts would create principal-store ambiguity in `end_user_id`. Flag to reviewers as designed.
- **Stale items are surfaced, never auto-dropped** — silent cart shrinkage is hostile UX and masks catalog mistakes; checkout (V3-P3) is where stale items become a hard 422.
- **Qty replace (not sum) on re-add** — idempotent retries from flaky consumer UIs beat surprise quantity doubling; flagged interpretation.
- **One hydration query per distinct collection** keeps `GET /cart` at O(collections-in-cart), bounded by the 50-item cap.
