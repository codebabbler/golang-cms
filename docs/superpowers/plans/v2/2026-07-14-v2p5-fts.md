# V2-P5 — Full-Text Search Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Per-collection weighted FTS over `text` and `richText` fields (Tiptap plaintext included) with ranked search endpoints and config-triggered reindexing — UAC-2.1, F-18, EC-12.

**Architecture:** `search_config` (JSONB on `cms_collections` since migration 0001) names fields and A–D weights. Setting it makes `schema.Engine` add a generated `search_tsv tsvector STORED` column plus GIN index **inside the same advisory-locked transaction** as any triggering change (EC-12: search is never stale relative to committed schema). Rich text feeds the column through `cms_tiptap_text(jsonb)`, an IMMUTABLE SQL function (migration 0007) — SQL, because only SQL can back a generated column. Ranked reads live in `internal/query` (BR-SCHEMA-3) with scope and `Decision` visibility identical to list reads. `'english'` is the fixed regconfig (documented; per-collection language is out of scope).

**Tech Stack:** Go 1.25, Postgres FTS (tsvector/GIN, bundled), Svelte 5, Playwright.

**Files:**

- [ ] **Step 1: Failing test** (integration): `SELECT cms_tiptap_text($1)` over a fixture Tiptap doc (heading + two paragraphs + bold span) returns all fragments space-joined; NULL → `''`; `'{}'::jsonb` → `''`.
- [ ] **Step 2:** FAIL (function absent). **Step 3: Migration:**

```sql
-- 0007: Tiptap plaintext extractor for generated tsvector columns (F-18, EC-12).
-- SQL because generated columns can only call IMMUTABLE SQL; the Go-side HTML
-- renderer (internal/richtext, V2-P4) serves responses, this serves indexing.
CREATE FUNCTION cms_tiptap_text(doc jsonb) RETURNS text
LANGUAGE sql IMMUTABLE PARALLEL SAFE AS $$
  SELECT COALESCE(
    (SELECT string_agg(t.v #>> '{}', ' ')
       FROM jsonb_path_query(doc, 'strict $.**.text') AS t(v)),
    '')
$$;
```

(`strict $.**.text` walks all depths; `#>> '{}'` unwraps the jsonb string. If the strict-mode path errors on scalar input on the deployed PG16 point release, switch to `lax` — the test suite decides; both satisfy the contract.)

- [ ] **Step 4:** PASS. **Step 5: Commit** — `git commit -m "feat: cms_tiptap_text immutable extractor — migration 0007 (EC-12)"`

**Interfaces:**
- Produces:
  - `schema.SearchConfig{Fields []SearchField}`; `schema.SearchField{Slug string; Weight string}` (JSON `{"fields":[{"slug":…,"weight":"A"}]}`).
  - `schema.ValidateSearchConfig(col Collection, cfg SearchConfig) error` — weight ∈ A–D; slug names an existing field of type `text` or `richText` (anything else → error naming slug and reason); ≤ 16 entries; no duplicate slugs.
  - `schema.OpSetSearchConfig{CollectionID uuid.UUID; Config SearchConfig}` — handled by `Apply`: validate → inside the standard locked tx: persist the JSONB on `cms_collections`, then **regenerate**: `DROP COLUMN IF EXISTS search_tsv` (index falls with it), and when `Config.Fields` non-empty, `ADD COLUMN search_tsv tsvector GENERATED ALWAYS AS (<expr>) STORED` + `CREATE INDEX "ix_<table>_search_tsv" ON "<table>" USING gin (search_tsv)`. Expression per field: `text` → `setweight(to_tsvector('english', coalesce("<col>",'')), '<W>')`; `richText` → `setweight(to_tsvector('english', cms_tiptap_text("<col>")), '<W>')`; fields `||`-concatenated.
  - **Regen hook (EC-12):** the existing field-drop and field-type-change ops, when the field appears in the collection's `search_config`, remove it from the config and run the same regen **in their own transaction** — search never references dropped fields, enforced by construction. The op's audit event carries `duration_ms` (the rebuild stall operators schedule around — 08) and `detail: {searched_fields}`.
  - Exposed as `PUT /api/admin/collections/{id}/search-config` (`RequireSession`+`RequireCSRF`+`RequireRole(admin)` — same floor as other schema ops; re-validate the V1 floor and match it).

## Self-Review Notes (execution-time attention)

- **`'english'` regconfig** is pinned and documented; revisit only via a requirements cycle (O-6 localization is the named future).
- **Regen = drop + re-add generated column** rewrites the table (ACCESS EXCLUSIVE) — that IS the documented EC-12 stall; do not "optimize" it into a trigger-maintained column (that's 03's explicitly-not-adopted alternative).
- **Weight semantics:** A–D map to Postgres's native weights; UAC-2.1's "per-field weights" is satisfied by the setweight expression, and ranking uses `ts_rank_cd` defaults — no custom weighting curve (YAGNI).
- **`search_tsv` in projections:** the column must be excluded from `SELECT *`-style record serialization (V1 strips `deleted_at` already — add `search_tsv` to the same strip list; the Task 4 hidden-field test catches leakage).
- **Admin search floor:** viewer-and-above can search what they can list (scope parity); no separate search permission (YAGNI).
