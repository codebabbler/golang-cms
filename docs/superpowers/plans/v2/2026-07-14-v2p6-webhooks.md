# V2-P6 — Webhooks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Lifecycle events (create, update, publish, trash) deliver HMAC-signed webhooks within 30 seconds through a durable Postgres outbox with bounded retry and SSRF-safe egress — F-22, UAC-2.2 (webhook half), new BR-HOOK-1/2.

**Architecture:** `cms_webhooks` (registry, secrets sealed at rest) + `cms_webhook_deliveries` (outbox). Lifecycle mutations enqueue delivery rows **in the same transaction** via a `TxHook` seam on `lifecycle.Service` (nil in V1 wiring — behavior unchanged until registered). A `webhooks.Deliverer` goroutine (post-commit nudge channel + 15 s fallback ticker, own Start/Stop in `app.Run`'s EC-14 ordering) signs and posts with a pinned-IP, redirect-refusing HTTP client. `record.publish` doubles as the purge-on-publish signal (04 amendment).

**Tech Stack:** Go 1.25, pgx/v5, sqlc, HMAC-SHA256, Svelte 5, Playwright.

### Task 4: Deliverer — signing, SSRF guard, retry; BR-HOOK-1/2 land

**Files:**
- Create: `internal/webhooks/deliverer.go`, `internal/webhooks/ssrf.go`
- Modify: `internal/app/app.go` (Start/Stop ordering: deliverer stops with the tickers, before drain — EC-14), `docs/BUSINESS_RULES.md`, `docs/architecture/05-auth-security.md`, `docs/architecture/08-observability.md`, V1 secret-log test file
- Test: `internal/webhooks/deliverer_test.go`, `internal/webhooks/ssrf_test.go`

**Interfaces:**
- Produces:
  - `webhooks.NewDeliverer(q *store.Queries, masterSecret string, log *slog.Logger, opts ...DelivererOption) *Deliverer`; `(*Deliverer).Start(ctx)` — loop: `select` on nudge channel / 15 s ticker / ctx; each wake: `ClaimDueDeliveries` batch, deliver sequentially, repeat until no due rows. `(*Deliverer).Stop()` waits for the in-flight batch. `(*Deliverer).Nudge()` (non-blocking send, buffered 1).
  - Delivery: open the webhook's secret; body = stored payload JSONB; headers `Content-Type: application/json`, `X-CMS-Delivery: <id>`, `X-CMS-Event`, `X-CMS-Timestamp` (RFC 3339 now), `X-CMS-Signature: sha256=<hex HMAC-SHA256(secret, timestamp + "." + body)>` (**BR-HOOK-1**). 2xx → `MarkDelivered`; else/error → attempt < 5 → `MarkRetry` with backoff `15s, 2m, 15m, 1h` after failures 1–4; attempt 5 → `MarkFailed`. Per-attempt timeout 10 s; response body read ≤ 4 KiB, discarded; `last_error` truncated 512 chars and **never contains the signature or secret**.
  - `ssrf.go` (**BR-HOOK-2**): `safeTransport(allowPrivate bool) *http.Transport` — `DialContext` resolves the host itself, rejects every resolved IP that is loopback/private/link-local/multicast/unspecified (v4 AND v6, `netip` classification), dials the **first permitted resolved IP literally** (pinned — no second resolution, no TOCTOU rebind); client `CheckRedirect` returns an error always (no redirects, period). `DelivererOption`: `AllowPrivateTargets()` — applied only from `//go:build e2e`-tagged wiring and `_test.go` files; the production build cannot reach it (compile-time seam, spec B4).
  - `docs/BUSINESS_RULES.md` §Webhooks (new subsection, after AUDIT): **BR-HOOK-1** "Every webhook delivery is HMAC-SHA256-signed over `timestamp.body` with a per-endpoint secret generated server-side, shown once at creation, sealed at rest, and never logged or re-exposed. Enforced in `webhooks.Deliverer` (signing) and `webhooks.Service` (secret lifecycle)." **BR-HOOK-2** "Webhook egress denies loopback, private, link-local, multicast, and unspecified destinations for every resolved address, pins the dialed IP to the resolution that passed the check, follows no redirects, and re-resolves at each delivery. Enforced in `webhooks.safeTransport`."
  - `TestNoSecretsInLogs` regexes += `whsec_[A-Za-z0-9_\-]{20,}`, `X-CMS-Signature`, `sha256=[0-9a-f]{64}`.
  - `jobs.Retention` duty 9: `DeleteOldDeliveries(now-7d)`; 08 amendment: `jobs.Webhooks` telemetry (per-wake `delivered`, `retried`, `failed` counts) + retention duty line; 05: SSRF mitigation present-tense.

## Self-Review Notes (execution-time attention)

- **TxHook error aborts the mutation** — deliberate and load-bearing (outbox atomicity). The alternative (best-effort enqueue) silently drops contracted webhooks; rejected. Flag to reviewers as designed behavior.
- **Post-commit nudge seam:** pgx lacks commit hooks; the plan's "hook returns a PostCommit func" fallback is acceptable — choose the cleanest at execution and note it in the 07 amendment if it changes the seam shape.
- **Sequential delivery, batch 20, single worker:** sized to design load; `FOR UPDATE SKIP LOCKED` already makes a future worker-pool safe. Do not add concurrency now (YAGNI).
- **Registry snapshot 30 s staleness** affects only *new* webhooks' first events; documented, acceptable, and refreshed on every deliverer wake.
- **`whsec_` prefix** mirrors the `cms_` API-key convention; secret-scanning tools key on stable prefixes (same rationale as V1).
- **BUSINESS_RULES gains a new section** — run the `br-traceability-testing` skill's checklist when amending; BR-HOOK IDs must appear in the trace script's universe (it greps the manual — verify new rules are picked up automatically).
