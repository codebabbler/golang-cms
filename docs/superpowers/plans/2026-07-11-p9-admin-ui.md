> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The complete embedded admin SPA — every screen of `06-admin-ui.md` over the frozen P2–P8 API — plus the CSP hardening, closing with the V1 delivery gate: UAC-1.1…1.6 end-to-end through the UI, `make test && make trace && make bench` green, trace waiver file empty.

**Architecture:** Svelte 5 + Vite only (no SvelteKit — O-5), runes for state, module-scope rune stores, one typed API client wrapping fetch. The server side gains only response headers (CSP/nosniff/Referrer-Policy). Tiptap bundles at build time and exchanges canonical JSONB with the API.

**Tech Stack:** Svelte 5, Vite 7, @tiptap/core + @tiptap/starter-kit (npm dev-side; the binary's runtime dependency set is unchanged — BR-RUNTIME-2), Playwright for the UAC end-to-end gate (dev/CI only), vitest for component tests.

## Global Constraints

- Svelte 5 runes (`$state`, `$derived`, `$effect`); shared state in module-scope rune stores; NO external state library (06).
- ONE API client module: parses the 04 envelope, converts `error.code` to typed failures, attaches `X-CSRF-Token` on every mutation, redirects to login on `401` (06).
- CSRF token in memory only — never localStorage, never a readable cookie (BR-AUTH-4); hard refresh refetches via `GET /api/admin/auth/csrf`.
- Re-auth modal: a `403` whose details carry `{"reason":"recent_auth_required"}` triggers a password re-prompt (re-login), then retries the original request (BR-AUTH-5); destructive flows surface it BEFORE submission when the 4-hour window has lapsed (client tracks last-login time).
- Rich text: Tiptap exchanging canonical JSONB — the editor never produces HTML for storage; rendering only through Tiptap's schema-constrained renderer, never `innerHTML` (06 §Security).
- CSP served on SPA and `/api/admin` responses exactly per 06: `default-src 'self'; img-src 'self' <media-domain>; media-src 'self' <media-domain>; frame-ancestors 'none'` — no inline scripts; plus `X-Content-Type-Options: nosniff` and `Referrer-Policy: strict-origin-when-cross-origin`. `<media-domain>` = origin of `R2_PUBLIC_BUCKET_URL` (omitted in media-less mode).
- Session cookie is browser-managed (`HttpOnly`); the SPA never reads or writes it.
- Destructive actions demand typed confirmation client-side AND rely on the server gate (BR-SCHEMA-7): collection/field drops, purge, media delete, key revocation.
- Every list that shows totals requests `?count=exact`; cursor-aware next/prev paging past the 10,000-offset ceiling (06 Content editor).
- The V1 delivery gate (11-roadmap): UAC-1.1…1.6 pass end-to-end; `make bench` meets N-3/N-4; CI `trace` green with an EMPTY waiver file.
- Commits plain; branch `main`. This plan may be split into two execution passes at the Stage A/B boundary below without renegotiation.

## Stage A

### Task 1: API client, auth store, router, shell

**Files:**
- Create: `web/src/lib/api.js`, `web/src/lib/stores/auth.svelte.js`, `web/src/lib/router.js`, layout shell components; vitest config.

**Interfaces (the client contract every screen consumes):**

```js
// web/src/lib/api.js — the ONE fetch wrapper (06 §SPA Conventions).
// api.get(path, params?) / api.post(path, body?) / api.put / api.del
// → resolves to envelope.data (meta available via api.getWithMeta)
// → throws ApiError{code, message, details, status}
// Behavior:
//  - mutations attach X-CSRF-Token from the auth store (memory only)
//  - 401 → auth.clear() + router.go('/login') + throws
//  - 403 with details.reason === 'recent_auth_required' → throws
//    RecentAuthRequired (screens funnel it to <ReAuthModal retry={fn}>)
//  - never caches; JSON only; body errors surface field details verbatim
export class ApiError extends Error {}
export class RecentAuthRequired extends ApiError {}
```

- `auth.svelte.js`: `$state` for `{user, csrfToken, lastLoginAt}`; `login(email, pw)` (stores csrf from body, stamps `lastLoginAt`), `refreshCsrf()` (hard-refresh path), `logout()`, `recentAuthFresh()` (< 4 h — drives pre-submission re-auth prompts).
- `router.js`: hash routing (`#/collections/:slug/records/:id`), `route` rune store, `go(path)`; guards: unauthenticated → `/login` except `/setup`, `/recover`.
- Shell: nav (Collections, Media, Users, API Keys, End Users), active session display, logout.

- [ ] **Steps:** vitest tests for the client (envelope unwrap, error typing, CSRF header presence on POST, 401 redirect hook, recent-auth typed throw — mock fetch) → implement → `cd web && npx vitest run` PASS → `make build` still green → commit `feat(ui): typed API client, auth store, router shell`.
